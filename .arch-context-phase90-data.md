(5) Trust accounts carry no currency, so use the org default currency (as `MatterTrustBalanceResponse` does). The repository method goes in `TrustTransactionRepository` (read-only `@Query`); the service method goes in `DashboardService` beside `getTrustPosition` |

## 6. Fees billed vs collected per month

| Item | Finding |
|---|---|
| Existing | **No series anywhere.** `CashDigestService.BILLED_COLLECTED_SQL` (`:117-126`) computes scalar `billed` and `collected` for a **trailing 7 days** only (internal email). `reporting/` ships three report slugs (`timesheet`, `invoice-aging`, `project-profitability`; `StandardReportPackSeeder.shipped`, `:335-341`), none of them billed or collected. `report/ReportController` covers profitability and utilization only. `InvoiceController` exposes `outstanding-summary` (scalar) and a list. The only `date_trunc` series in the backend is `TimeEntryRepository` (hours) |
| Data | Billed: `invoices.issue_date` (LocalDate, a business date), `invoices.total`, `invoices.currency`, `invoices.status` (DRAFT, APPROVED, SENT, PARTIALLY_PAID, PAID, …). Collected: `payment_events` (`invoice/PaymentEvent.java`: `amount`, `currency`, `status` (COMPLETED), `created_at` Instant, `provider_slug` manual/trust_fee_transfer/xero/PSP). There is **no payment business-date column**, so the month must come from `created_at AT TIME ZONE 'Africa/Johannesburg'` (`KaziTime.ZONE_ID`). Alternative: `invoices.paid_at` (Instant) + `amount_paid`. The digest uses `paid_at`, PAID only, which **misses part payments** (622D D-3 follow-up) |
| Proposed | `GET /api/reports/billing-trend?months=12` (clamped 1–24; optional `to` month defaulting to `YearMonth.now(clock)`), placed in `report/ReportController` next to `/api/reports/profitability` with `@RequiresCapability("FINANCIAL_VISIBILITY")` (same as profitability and `outstanding-summary`). Response: `{currency, from:"2025-12", to:"2026-11", months:[{month:"2026-06", billed, billedCount, collected, collectedCount}]}`. Billed = `SUM(i.total)` where `i.currency=:currency AND i.status IN ('SENT','PARTIALLY_PAID','PAID') AND i.issue_date BETWEEN :start AND :end`, grouped by `date_trunc('month', i.issue_date)`, matching the digest's billed definition. Collected = `SUM(pe.amount)` where `pe.status='COMPLETED' AND pe.currency=:currency AND pe.created_at >= :startInstant AND < :endInstant`, grouped by `date_trunc('month', pe.created_at AT TIME ZONE 'Africa/Johannesburg')`. This includes part payments and trust fee transfers. Zero-fill months in Java |
| Subtleties | (1) Window bounds come from `LocalDate.now(clock)`. Instant bounds = `start.atStartOfDay(KaziTime.ZONE).toInstant()`, never DB `CURRENT_DATE` (JVM/DB zone is UTC in prod). (2) Default currency only (`orgSettingsService.getDefaultCurrency()`), like `outstandingSummary`. (3) Totals include VAT (`total`); state that in the chart caption or ADR. (4) A fee note voided after issue drops out of "billed" (status filter), matching digest semantics. (5) Decide in the ADR whether collected = payment_events (recommended, includes part payments) or `paid_at` (digest parity); the two disagree for part-paid notes |
| Verdict | **MISSING** |

## Notes / flags for /architecture

1. KPI redaction is role-only and leaks `previousPeriod.billablePercent` to members (`KpiResponse.withFinancialsRedacted` keeps `previousPeriod`). The UI can hide it, but the leak is a backend defect. Fixing it is a behaviour change, which makes it a re-spec or a separate bug, not part of Phase 90.
2. KPI deltas for active matters and overdue tasks are always 0 (both are point-in-time). Render those tiles with **no delta**, not a "0%" delta.
3. `averageMarginPercent` is always null, so hide the tile or populate it in the existing endpoint (a backend slice).
4. The trust page's reconciliation card is broken by a stale hard-coded null (`trust-accounting/actions.ts:126-127`). Moving to `trust-position` fixes it as a side effect; call that out in the PR.
5. Utilization is restricted by role, not capability, so a FINANCIAL_VISIBILITY non-admin sees only their own bar.
6. `CashDigestService.TOTALS_SQL` and the invoice-aging report summary both sum across currencies. Any new aging or billing endpoint should filter to the org default currency, like `outstandingSummary`.
7. `matters/[id]` fetches `getMatterBudget` twice (page:302 and inside KPIDashboard). The hero extraction is a natural point to fetch once (a visual-only refactor).
