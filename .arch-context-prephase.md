Governing rule (PR body, mirrored in `KaziTime` Javadoc): a business calendar date or wall-clock time a user reasons about is SAST; wire formats, storage instants, sort keys, provider billing months and audit-export timestamps stay UTC.

Generated-document object keys carry a **fresh random UUID per upload** as a path segment between the family and the file name. ## 10. ADR skeletons for the three shipped decisions (facts only — numbering is the architect's call; last ADR referenced in the repo docs is ADR-357)

### ADR-A — One product-wide business zone (Africa/Johannesburg) read through the injected `Clock`
- **Context.** `BackendApplication.clock()` was `Clock.systemDefaultZone()`; containers run UTC; 57 zone-less `LocalDate.now()` sites in 32 files (requirements §28). A fee transfer at 01:30 SAST was dated the day before the deposit that funded it (G88-F48, HIGH); the Next.js server computed "today" in UTC (G88-F49). Founder decision: one zone for the whole product, no per-firm setting, no container `TZ`.
- **Decision.** (1) `config/KaziTime.ZONE_ID = "Africa/Johannesburg"` / `ZONE`; the `Clock` bean is `Clock.system(KaziTime.ZONE)`. (2) Every server-side business "today" is `LocalDate.now(clock)`; a stored `Instant` becomes a business date via `KaziTime.ZONE`; `@Scheduled(cron)` carries `zone = KaziTime.ZONE_ID`; firm-authored automation crons evaluate in SAST; SQL `CURRENT_DATE` is replaced by a bound `:today`. (3) Governing rule: user-facing calendar dates/times are SAST; wire formats, storage instants, sort keys, provider billing months and audit-export timestamps stay UTC, and each such site is on a commented allow-list. (4) Frontend/e2e read "today" from `@b2mash/shared/date` (`todayInSA`, `isoDateInSA`, `daysBetween`); Playwright `timezoneId` defaults to SA. (5) Enforcement: `architecture/ZoneAwareTimeArchTest` (5 ArchUnit rules, §1) — adding an allow-list entry is a review-time decision. (6) Tests pin the clock with a nested `@TestConfiguration` `@Primary` fixed clock; Surefire runs the JVM in UTC by default (`-Dtest.timezone` overrides for boundary runs).
- **Consequences.** No historical correction (no live firms; QA/demo rows). Legacy `retention_ends_on` backfilled in UTC stays. Stored reminder times not converted; label now says SAST. Four browser-zone frontend components remain outside the J8 list (follow-up). Time-reminder semantics = SA wall clock.
- **Evidence.** PR #1716, merge `a216f4430`; in-window lifecycle 101/0/3 at 01:08–01:11 SAST; DB read-back of Moroka postings; full verify 6304/0/0/26.

### ADR-B — Identity-based storage keys for generated documents
- **Context.** Keys were `org/{tenant}/generated/{slug}-{entitySlug}-{date}.pdf` (SoA: `-{periodEnd}`); any two documents with the same name overwrote each other and every row pointed at one object — a client downloaded an internal SoA in QA (G88-F33, HIGH).
- **Decision.** Key = `org/{tenant}/generated/{uuid}/{fileName}` where `uuid = UUID.randomUUID()` per upload (one token shared by a DOCX and its PDF sibling); built only by `S3PresignedUrlService.buildGeneratedKey`. File name unchanged and last segment (browser default save name unchanged; no `Content-Disposition` on this path). Bank-statement imports take the same `{uuid}/{fileName}` tail under `trust-statements/…`. One presign whitelist, `integration/storage/StorageKeyPolicy`, used by the S3 adapter and the in-memory test double; the flat legacy `generated/{fileName}` shape stays presignable. Readers always use the key stored on the row → no backfill. No data remediation; a read-only collided-row report query is documented in the PR body only (J5).
- **Consequences.** Objects are never overwritten; storage grows with every generation (no dedup). Legacy collided rows remain shared — retention/anonymisation purge of one row deletes bytes another legacy row points to (follow-up). `disbursement-receipts/…` keys sit outside the policy (hypothesis follow-up). Demo cleanup prefix mismatch (follow-up).
- **Evidence.** PR #1717, merge `3501fa899`; two same-period SoAs → two objects with different SHA-256 in LocalStack; full verify 6360/0/0/26.

### ADR-C — Contract parties are explicit matter fields, never `org.*` / `customer.*`
- **Context.** The Voetstoots clause named the firm (`org.name`) as the party not liable and the client (`customer.name`) as the purchaser; OTP "Seller:" was blank because `seller_name` had no field definition and `CustomFieldValidator` stripped it (G88-F12, HIGH).
