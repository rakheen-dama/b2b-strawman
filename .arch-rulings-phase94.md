# Phase 94 architecture rulings (orchestrator, 2026-11-28)

These are binding on the architecture doc (§19) and on ADR-397..403. If a ruling turns out wrong against the code, flag it in the doc's Founder decisions or Open questions. Do not silently diverge.

Founder go-ahead given 2026-11-28 to two adjustments:
- **A3:** the legal-za matter-template pack has no family/children template, so no template prefills CHILD. CHILD is ID-derived only; templates may prefill other s26 categories.
- **Owner-only list:** the new owner-only capability needs the backend OWNER_ONLY list and the frontend copy changed together, because a parity test checks them.

## R1. Package layout
- New top-level horizontal package `egress/`. It holds `classify/` (EgressCategory, detectors, SaIdNumber), `policy/` (policy versions, transfer basis, category unblocks), `token/` (dictionary, tokeniser, rehydrator), `ledger/` (events and subjects) and `EgressGuard` (the façade).
- The route adapters live beside their route:
  - route A: `integration/ai/skill/SkillEgressAdapter`, called from `AiSkillExecutionService`;
  - route B: `mcp/egress/McpEgressWriter` + `@EgressField` / `@EgressSubject` annotations (the annotations themselves live in `egress/classify`).
- **No new third-party dependency.** Name matching uses a small in-house trie / Aho-Corasick matcher.

## R2. Route A (in-product skills): tokenise → call → rehydrate
1. **Pre-call.** `executeSkill` assembles the prompts. Then `EgressGuard.prepareSkill(EgressRequest)` returns `PreparedEgress`, a sealed type:
   - `Blocked(List<BlockReason>)`, or
   - `Allowed(systemPrompt', userPrompt', TokenMap, EgressDisposition)`.
2. **Blocked.** The `AiExecution` is persisted with status **BLOCKED** (new status) and `block_reason`. There is **no provider call and no cost row**. The `egress.execution.blocked` audit and a ledger event with disposition BLOCKED are written.
3. **Post-call.** `LlmJsonParser.parse(raw)` → JsonNode → `Rehydrator` walks every textual node (Tiptap included) and substitutes placeholders → the result is re-serialised and handed to `createGates` and the CashDigest parse as the "raw output". The AiSkill interface does not change; the re-parse is idempotent.
4. **Unknown placeholders** (well-formed but not in the map) are left verbatim and counted in an `egressWarnings` field on the execution.
5. **Placeholder grammar:** `[[K:<TYPE>:<n>]]`, e.g. `[[K:CLIENT:1]]`, `[[K:PARTY:2]]`, `[[K:IDNUM:1]]`, `[[K:TAXNUM:1]]`, `[[K:EMAIL:1]]`. The regex is `\[\[K:[A-Z_]+:\d+\]\]`. A fixed system-prompt preamble (an egress notice) tells Claude to reproduce placeholders verbatim and never invent new ones. Prompt caching must keep working, so the preamble is static text placed before the cached system prompt.
6. **Token map is EPHEMERAL** (in memory, for one execution) and is never persisted. Consequences:
   - `AiExecution.outputContent` stores the TOKENISED raw output;
   - the AI history page shows placeholders and a "names and identifiers were tokenised" label;
   - gate payloads hold rehydrated real values (Kazi-internal data, same as today);
   - retry re-runs the whole skill.
   
   This removes token-map-at-rest risk (it shrinks RG-7). It is a founder decision (FD), and it is the recommendation.
7. **Name dictionary.**
   - **Scope:** per tenant. Sources: Customer.name, Customer contact name, PortalContact.displayName, AdverseParty.name + aliases, and matter custom fields `opposing_party` / `opposing_attorney`.
   - **Cache and refresh:** cached per tenant, invalidated on the relevant domain events, with a 10-minute TTL fallback.
   - **Matching:** longest-first, case-insensitive, word-boundary; minimum token length 3 chars after trimming. Names consisting only of generic words are skipped via a stop-list (e.g. "Trust", "Holdings").
   - **Token types:** CLIENT for Customer names, PARTY for adverse/opposing parties, CONTACT for contacts.
8. **Identifiers.** Known structured fields are classified by field. Free text is classified by detector. SA ID (13 digits, Luhn, plausible YYMMDD), passport (format), CIPC reg `\d{4}/\d{6}/\d{2}`, SARS tax/VAT (10 digits, leading digit rule), bank account (6–11 digits only when next to an account label, or a known field), email, ZA phone. ADDRESS is detected only from known fields.
9. **FICA.** Extracted document text is tokenised. `SaIdNumber` computes the facts locally: `idFoundOnDocument`, `luhnValid`, `matchesClientRecord`, `dobConsistent`. They are injected as a facts block. Claude never needs the raw number.
10. **Intake.** The 500-recent-matters list stays, tokenised (FD, recommended: keep 500, tokenised).
11. **Vision.** `completeWithVision` ⇒ `SPECIAL_BIOMETRIC`. It is blocked unless unblocked. When unblocked, `SkillExecutionRequest.confirmImageEgress=true` is also required for that run; without it the run is BLOCKED with reason `IMAGE_CONFIRMATION_REQUIRED`.
12. **Exempt:** `IntegrationService.validateKey` (no client data).
13. **Architecture test:** only `egress` and `integration/ai/anthropic` may reference `AnthropicApiClient`, and only `AiSkillExecutionService` may call `AiProvider.complete*`. Use the existing whole-codebase scanner style under `src/test/.../architecture/`.

## R3. Route B (MCP): classified DTOs, one writer
1. **Field classification.**
   - Every MCP DTO record component of type String, or a collection/array of String, carries `@EgressField(EgressCategory.X)` (or `NONE` for non-PI such as status, enum strings and ids).
   - `@EgressSubject(SubjectType.CLIENT|MATTER|ADVERSE_PARTY|CONTACT)` marks the id component that identifies the data subject or matter.
   - Scanner test `McpDtoEgressClassificationTest` fails on any unclassified component.
2. **Single serialisation point.** `McpEgressWriter.write(Object dto, McpEgressScope)` replaces the success path of `McpToolErrors.asResult(...)`. Tools never serialise PI themselves. A second scanner test forbids `ObjectMapper.writeValue*` / `valueToTree` in `mcp/tool` and `mcp/resource` except through the writer.
3. **How the writer works.** It serialises to a JsonNode and walks it with a per-DTO-class classification map (built reflectively once and cached). It applies, in order:
   - **NO_AI subject:** omit the element from lists; a direct get returns the existing non-leaking 404 (`McpToolErrors` convention);
   - **SPECIAL/CHILD matter:** keep id, reference, status and dates; replace name, description, FREE_TEXT, correspondence subject/body and document names with the marker object `{"withheld": "<REASON>", "category": "<CATEGORY>"}`, where REASON is SENSITIVE_MATTER, CHILD or NO_AI;
   - **identifier fields:** irreversible mask (last 4 visible for ID, bank and tax numbers; `j***@domain` for email; `*** *** 1234` for phone);
   - **FREE_TEXT:** detector-based identifier masking inside the text;
   - **names:** pass through.
   
   It then records the ledger.
4. **Enablement.** `McpEnablementService.effectiveState()` = integration enabled ∧ latest acknowledgement GRANTED ∧ a current `AiTransferBasis` exists with `mcpCommercialPlanAttested=true`. **No grace period** for already-enabled tenants: on deploy they turn off until the owner records the basis and attestation, with a banner on settings and in the MCP card (FD, recommended).
5. **Acknowledgement wording.** It is renamed "Firm acknowledgement: AI data egress", version `popia-egress-v2`. v1 rows are kept. A tenant whose latest GRANTED is v1 must re-acknowledge v2 (that is part of the same switch-off).
6. **Write tools.** Only the response payloads go through the writer.

## R4. Sensitivity, children, no-AI
1. **Columns.**
   - `projects`: `sensitive_categories` jsonb array of s26 category codes, default `[]`; `ai_excluded` boolean default false; `ai_excluded_reason` text; `ai_excluded_by` uuid; `ai_excluded_at` timestamptz.
   - `customers`: the same `ai_excluded*` columns.
   - `project_templates`: `default_sensitive_categories` jsonb, copied at instantiation.
2. **CHILD is derived, never stored.** A subject is CHILD if its SA ID number gives age < 18 at egress time. The century rule: YY > current YY ⇒ 19YY, else 20YY. It applies to the client (individual entity types) and to adverse parties linked to the matter (`AdversePartyLink`).
3. **Who can change the flags.**
   - **Matter flags:** anyone with matter edit access (`ProjectAccessService` canEdit) can set them. Clearing them needs the same access, is audited, and requires a reason (FD, recommended).
   - **Client `ai_excluded`:** `CUSTOMER_MANAGEMENT`.
3. **Unblocks.**
   - **`ai_category_unblocks`** is append-only. Fields: category, action GRANTED/REVOKED, basis `PRIOR_AUTHORISATION` (+ regulator_reference, authorisation_date) or `ADEQUACY_BINDING_AGREEMENT` (+ attestation text), reason_type `DATA_SUBJECT_CONSENT` / `RIGHT_IN_LAW` / `OTHER` + reason_text, document_reference, owner, timestamp.
   - **Scope:** an unblock applies tenant-wide per category. Per-matter unblocks are out of scope.
   - **Config gate:** the unblock endpoints sit behind `heykazi.egress.special-unblock-enabled=false` until RG-1 clears; the endpoint returns 403 with a ProblemDetail explaining why, and the UI shows the dialog disabled.
   - **Route A:** even when unblocked, the category is sent (not tokenised beyond names and identifiers) and recorded.
5. **New capability `AI_EGRESS_GOVERN`, OWNER_ONLY.** It gates the transfer basis, unblocks and their revocation. `AI_MANAGE` gates the identifier policy matrix. Reads of the egress log: `AI_MANAGE` firm-wide. The client "AI disclosures" panel is gated by `CUSTOMER_MANAGEMENT` (same as the client detail).

## R5. Policy and transfer basis
1. **`ai_egress_policy_versions`** (append-only): version int unique, rules jsonb, changed_by, changed_at.
   - **What is configurable:**
     - identifiers (NATIONAL_ID, PASSPORT, COMPANY_REG, TAX_NUMBER, BANK_ACCOUNT, EMAIL, PHONE, ADDRESS): ALLOW | MASK, default MASK;
     - route-A names (PERSON_NAME/PARTY_NAME): ALLOW | TOKENISE, default TOKENISE.
   - **What is not configurable:** FREE_TEXT identifier masking is always on; special/child/biometric are BLOCK unless unblocked (R4); NO_AI is always BLOCK.
   - **No row** ⇒ code defaults, reported as version 0. The first save creates v1.
   - **Relaxing** a category (MASK→ALLOW or TOKENISE→ALLOW) requires a reason_text stored in rules jsonb per category.
2. **`ai_transfer_bases`** (append-only versions; the current one is the latest):
   - provider_legal_entity (default "Anthropic PBC") and provider_country (default "United States");
   - s72_grounds jsonb set {BINDING_AGREEMENT, CONSENT, OTHER} + other_text;
   - commercial_terms_dpa_attested bool + attested_date;
   - zero_data_retention enum YES/NO/UNKNOWN;
   - mcp_commercial_plan_attested bool;
   - recorded_by, recorded_at, version.
   
   It is the prerequisite for any route A call (else BLOCKED, reason TRANSFER_BASIS_MISSING) and for MCP enablement (R3.4).
3. **Policy and basis versions are snapshotted** on every ledger event.

## R6. Ledger
1. **`ai_egress_events`:**
   - id, route SKILL|MCP, skill_id or tool_name;
   - ai_execution_id (nullable FK);
   - member_id, project_id (nullable);
   - provider_legal_entity, provider_country, purpose;
   - disposition SENT|BLOCKED, block_reasons jsonb;
   - policy_version, basis_version;
   - free_text_sent bool, image_sent bool;
   - occurred_at.
2. **`ai_egress_subjects`:** id, event_id, subject_type CLIENT|ADVERSE_PARTY|CONTACT, subject_id, categories jsonb `{category: SENT|MASKED|TOKENISED|WITHHELD}`.
   - Index `(subject_type, subject_id, occurred_at)`; denormalise occurred_at onto subjects.
3. **Raw values are never stored** (invariant, with a test).
4. **Route A transactions.** The ledger is written in the same transaction as the AiExecution completion or BLOCKED persist (`AiExecutionPersistenceService`), keeping the Phase 72 split of the HTTP call from the DB transaction.
5. **Route B transactions.** `EgressLedgerService.recordMcp` uses REQUIRES_NEW and is called by the writer before the response is returned. If the response then fails, the result is over-reporting, which is accepted (prefer over-report to under-report; FD).
6. **Retention.** It follows the audit-event retention. DSAR anonymisation keeps the rows; the subject id still points at the anonymised customer, so there is no PI.
7. **DSAR export.** New section "AI providers and disclosures": provider, country, and the events about the subject (date, route, purpose, categories with disposition, disposition).

## R7. POPIA documents
- **Processing register.**
  - New nullable `system_key` varchar unique column on `processing_activities` (check the entity for an existing active/status field; if there is none, add `active` bool default true).
  - When AI or MCP is first enabled or the basis is recorded, upsert the `AI_ASSISTED_LEGAL_SERVICES` row: recipients "Anthropic PBC (United States)", legal basis from s72 grounds, categories from the current policy.
  - It is re-synced on policy or basis change. When AI is disabled the row is marked inactive, not deleted.
- **PAIA manual.** compliance-za pack v1 → v2 adds the part "Transborder flows of personal information" (s51(1)(c)/(d)-style), fed by `PaiaManualContextBuilder` from the current basis.
- **Clauses.** legal-za clause pack v3 → v4 adds the clauses `ai-use-disclosure` (engagement-letter AI clause: s18 notice + s72(1)(b) consent + right to exclude AI) and `ai-privacy-notice` (paragraph). The legal-za template pack v16 → v17 references `ai-use-disclosure` as an optional clause in the three engagement letters. Copy is RG-8 (attorney).
- **Wording lint.** A test forbids `/anonymi[sz]ed|de-identified|POPIA-exempt/i` in AI/egress/MCP frontend directories and backend egress messages. DSAR anonymisation surfaces are excluded.

## Corrections (2026-11-28, verified by the ADR writer against the code)
- **R3.2.** `McpToolErrors.asResult` is the error path only. On success, tools `return dto` and Spring AI serialises it, so the success return must go through `McpEgressWriter.write(dto, scope)`. Enforcement is the DTO classification scanner plus a test that every tool/resource invocation records exactly one ledger event.
- **R3.3.** NO_AI omission happens before pagination; otherwise `McpPage.total` leaks the excluded count.
- **R2.3/R2.6.** `CashDigestService` (~:320) and `AiSkillController` (~:135) read `outputContent`, which is tokenised. They must read a transient rehydrated-output field on `SkillExecutionResult` instead; it is never persisted.
- **R4.2.** ID-derived CHILD misses minors without an SA ID. The attorney may also tick CHILD as a matter sensitive category. Templates still never prefill it. This is an open question / FD; recommendation: accept for v1, with the RG-4 disclaimer.
- **Additions.** An unblock also lifts the matching MCP withholding. A route A call that fails after the request was sent is still recorded as SENT.

## Corrections 2 (2026-11-28, independent architecture review; verified against code at `382f9f694`)
- **Documents (new FD-20).** `McpDownloadUrl` has no subject id; `get_document_url` resolves document → matter → client before issuing: NO_AI → 404 + BLOCKED, SPECIAL/CHILD → marker and no link, else link + SENT with new `ai_egress_events.document_content_sent`. Same resolution for `attach_document`; `search_documents` withholds names on sensitive matters. Unmasked documents added to residual risk / RG-5.
- **R3.3 refined.** SQL-paged tools (`list_correspondence`, `get_matter_activity`, `get_audit_events`, `list_trust_transactions`) push the exclusion into the service query; in-memory filtering only for materialise-then-paginate tools. `total` asserted per tool.
- **Tokenisation.** Policy `ALLOW` skips replacement only; matching always runs (record-only), so `NO_AI_SUBJECT_MENTIONED` still fires.
- **Preflight** checks `ProjectAccessService.requireViewAccess` before reading flags.
- **Writer** fails closed on unclassified paths (`UNCLASSIFIED` marker + ERROR log). Coverage test uses per-tool fixtures (`tool-contract.json` has no call args) and exempts `kazi_ping`.
- **Route A transactions.** SENT ledger written with the cost row; rehydration + `createGates` inside the existing try → FAILED-with-cost, ledger kept. Model output is plain strings, not Tiptap.
- **Anonymisation** nulls `ai_excluded_reason` (customer + linked matters). **Collections scan** pre-filters NO_AI debtors, recording nothing (FD-11).
- **MCP p95 baseline** captured in 94D before the writer. Bypass test also scans for the Anthropic base URL / new HTTP clients (`AnthropicLlmProvider` exempt), excluding test classes. **FD-21:** firm-wide egress log shows matter names regardless of matter access (accepted, `AI_MANAGE` is admin-level).
