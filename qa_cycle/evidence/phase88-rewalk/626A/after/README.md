## Notes and surprises
- **The member can read the banking details through `GET /api/settings`.** `/api/settings/letterhead` is gated on TEAM_OVERSIGHT (Carol gets 403), but the aggregate `GET /api/settings` returns the same 16 fields, including `bankAccountNumber`, to a member (`06f-carol-get-settings.txt`). This matches the brief's expectation and the existing settings-plane design: `taxRegistrationNumber`, `informationOfficerEmail` and others are already member-readable there. It still makes the `/letterhead` GET gate cosmetic for confidentiality. Flagging it for the orchestrator to rule on; it is not a FAIL against the spec as briefed.
- The "Bob Admin" match in the audit PII scan is the framework-added `actor_name` (Bob was the actor). It is not the signatory value, even though the test signatory was briefly set to "Bob Admin". `07d` shows the hit is absent from every non-`actor_name` key.
- A screenshot could not be written straight into the worktree (the Playwright MCP's allowed roots are limited to the main checkout). It was saved under `b2b-strawman/.playwright-mcp/` and moved here. The stray snapshot `.yml` files were removed.
- Presigned LocalStack `logoUrl` query secrets in the captured responses are redacted (`X-Amz-Signature=REDACTED`, etc.).
