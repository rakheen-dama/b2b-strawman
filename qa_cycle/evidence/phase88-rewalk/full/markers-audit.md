## How the markers work

- **Hook** `.claude/hooks/pre-pr-merge-gate.sh` (unchanged since #1587, 2026-10-19; registered in `.claude/settings.json:19` as `"$CLAUDE_PROJECT_DIR/.claude/hooks/pre-pr-merge-gate.sh"`). It reads the changed files with `gh pr diff --name-only` (`:180-185`; an empty list — e.g. a diff past ~300 files — is a deny). `^backend/` needs `verify-backend.json`, `^frontend/` needs `verify-frontend.json`, `^portal/` needs `verify-portal.json`, and `^packages/` needs the frontend **and** portal markers (`:191-195`). Nothing else needs a marker.
- The marker checked is the **local file** `$REPO_ROOT/.claude/markers/verify-<area>.json`, where `REPO_ROOT = $CLAUDE_PROJECT_DIR` (`:131-132`), i.e. the checkout the merging session runs in. It must exist, have mtime ≤ 24 h (`:207`, `:218-224`), `"exit": 0` (`:226-232`), and a `"commit"` that is an ancestor of the PR head (`:234-249`). The `ts` field is **not** checked.
- For every PR, docs-only included, the body must also carry two `## Verdict: APPROVE @<7–40 hex>` lines that prefix-match the head (`:266-284`) and a `## CodeRabbit: (REVIEWED|DEFERRED)` line (`:286-289`).
- There are only three marker files, and each slice overwrites them. The per-PR **evidence** is therefore the version **committed** for that PR. Normally that is the post-merge bookkeeping commit `docs: Slice <id> done (#N)` on main. The exceptions are #1651 and #1678 (markers inside the PR squash) and #1692 (its docs commit also rewrote the backend marker).
- **Current files vs HEAD.** At `20559c3d6` the three files are the 628I gate markers @`cb10c5d63` (`138119b81`): BE 6290 tc / 0 F / 0 E / 26 skip; FE vitest 434/3551/2; PORTAL vitest 45/256. `git diff --stat cb10c5d63..HEAD -- backend frontend portal gateway packages compose` is empty (0 lines, re-run 2026-10-30).

What the script does per PR (`logs/629C-markers-derive.py`):
1. **Squash and parents:** `git rev-list --parents -n1 <squash>`. All 71 squashes have one parent.
2. **Areas:** `git diff --name-only <squash>^1 <squash>`, mapped with the hook's regexes.
3. **Marker-bearing commit:** the squash itself if `git show --name-only --format= <squash> -- .claude/markers/` lists a file, then `git log --format=%h --grep="(#N)" --fixed-strings -- .claude/markers/`. For each candidate, only the marker files **that commit changed** are used (the tree also holds older markers for other areas), and the first commit that changed an area wins. That ordering removes the `(#1651)` false positive (`8dfe4681b`, 619E's docs commit, which mentions #1651).
4. **Fields:** `git show <mc>:.claude/markers/verify-<area>.json` → `commit` / `command` / `exit` / `ts` / `summary`. **Ancestry:** `git merge-base --is-ancestor <marker.commit> <headRefOid>`, reported as "= head" when the head starts with the marker commit. All PR heads were present locally; no ancestry check failed for lack of an object.
5. **Verdicts:** regex `^## Verdict: APPROVE @([0-9a-fA-F]{7,40})\s*$` over the body, counted as bound when `headRefOid.lower().startswith(sha.lower())`. **CodeRabbit:** `^## CodeRabbit: (.*)$`.
6. `ts` is compared with `mergedAt` (both parsed as timezone-aware datetimes). Rows where the committed `ts` is later than the merge are flagged ⚠ (see Observations).

Gate-only commits and the direct commit (§ "Commits without a PR") were read with `git show <c>:.claude/markers/verify-<area>.json` for each file `git show --name-only --format= <c> -- .claude/markers/` lists. Coverage of the five missing-marker PRs: `git merge-base --is-ancestor <squash> bd32f07ff` returns true for `211a6dfc8`, `44c123007`, `011028434`, `1fe9799a0` and `4e7fc7827`.
