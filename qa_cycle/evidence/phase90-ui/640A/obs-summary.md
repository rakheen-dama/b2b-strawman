## Diary `data-columns`: not observable on this seed

All 17 captures show "Nothing in the diary today" (0 rows). When the list is empty `TodaysDiaryList` renders a `<p>`, not the `<ul>`, so `data-columns` is **absent** (recorded as null, row count 0).

The CardContent is `container-type: inline-size`, with a content box of 670px at 1024 and 1086px at 1440. So @4xl (896px) is eligible only at 1440, which is the same as the pre-fix run.

Whether the list switches to two columns at 4 or more rows, and stays at one column for 1–3 rows, is therefore covered **only by vitest** (`home-diary-widget.test.tsx` "goes two-column at @4xl only with ≥ 4 visible rows", `todays-agenda.test.tsx`). It is not observed in the browser. The pre-fix synthetic DOM probe (`pre-fix-41c860fb8/diary-probe.cjs`) injected `<li>`s client-side, so it cannot exercise the new React-side row-count gate, and I did not re-run it. Seeding real diary events would need data writes outside this OBS scope.
