Stack: the mock-auth E2E stack (frontend on :3001, backend on :8081), rebuilt from worktree-epic-643A after the legal-lifecycle and legal-depth-ii suites ran. Date 2026-11-13. I did not rebuild or reseed it.
Browser: I used Node scripts with `@playwright/test` chromium (nvm node 20, headless), not the Playwright MCP. Sessions signed in through `/mock-login` → Sign In, as Alice (owner) or as Carol (member) via `#user-select`. Dark mode was set with `localStorage["kazi-theme"]="dark"` plus `colorScheme: dark`. The `<html>` class was confirmed `dark` in every dark session. I made no SQL writes.

## Scripts (run in this order, saved exactly as run)
1. `probe.cjs` → `probe-raw.json`: read-only APIs. Before the wizard there were no reconciliations.
2. `drive.cjs` → `drive-raw.json`: records the pre-reconciliation tiles (`summary-cards-pre-recon-1440.png`), then drives the wizard. New Reconciliation → Period End 2026-11-13 → Choose CSV File (`statement-2026-11-13.csv`) → Run Auto-Match (8 of 9 lines matched) → Review Matches. This created DRAFT `b767151c…`, then the known step-4 crash appeared ("Something went wrong", `TypeError … reading 'length'`, in `recon-step4-crash-1440.png`).
3. `observe.cjs` → `observe-raw.json`: everything else (read-only). Full-page shots grow the viewport to the document height and wait 3.5 s. Playwright's `fullPage` resize restarts recharts' draw-in animation, so its full-page shots show an empty plot (an artefact of the capture, not a product bug). The script also writes `chart-tooltip-last-point-1440-light.png`, but its x-tick locator missed. I deleted that file and replaced it with `chart-hover-nov-1440-light.png` from `tooltip-probe.cjs`.
4. `tooltip-probe.cjs` → `tooltip-probe-out.json`: mouse sweep across Nov, plus keyboard ArrowRight ×11.
5. `home-probe.cjs` → `home-probe-out.json`: one run of `observe.cjs` failed on Home because Playwright's strict mode matched two `trust-position-widget` elements, one of them outside `#main-content`. I could not reproduce this in 18 samples (exactly one widget each time). It is most likely the streamed RSC hidden segment caught mid-swap. I scoped the locator to `#main-content`.
6. `layout-probe.cjs` → `layout-probe-out.json` and `summary-cards-{768,1024,1280}-light.png`: measures StatCard value/icon overlap and overflow, and which transactions-table columns sit inside the visible scroller.

## Defects
- **D1 (regression):** `trust-transactions-table.tsx` cells do not wrap. The long `INT-CREDIT-<uuid>-<uuid>` references make the table 1299 px wide. At 1440 the AMOUNT and STATUS columns sit behind an inner horizontal scroll, and TYPE is also hidden at 1280 and below. Only DATE is visible at 768 and 1024. Before this PR the references wrapped and all 5 columns fitted at 1024 (`../before/trust-dashboard-post-1024.png`). Evidence: `trust-dashboard-1440-light.png`, `trust-dashboard-1024-light.png`.
- **D2:** the Trust Balance StatCard value "R 290 249,98" runs under the icon chip at 768 and 1280, covering the cents. At 1024 it is clipped past the card edge, and "Unbalanced" also runs under the icon. Clipping at 1024 existed before this PR; the icon overlap is new with the StatCard adoption. Evidence: `summary-cards-768-light.png`, `summary-cards-1024-light.png`, `summary-cards-1280-light.png`.
- **D3:** the chart's direct end-labels "Cashbook" and "Client ledgers" print on top of each other when the two series end close together (which is the normal trust case). Evidence: `chart-hover-nov-1440-light.png`, `chart-1440-dark.png`.
- **N1 (minor):** the last x-axis tick reads "Nov 2026" without "(to date)"; the tooltip and table do carry the label.
- **N2 (likely shared PageHeader, pre-existing):** at 768 the title and description are squeezed into a column about 130 px wide beside the action buttons (`trust-dashboard-768-light.png`).
