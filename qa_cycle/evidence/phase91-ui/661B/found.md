# 661B — out-of-scope findings (reported, not fixed)

Found while building 661B (light scheme A1, FD-1 option c). None is fixed in the 661B PR (root `CLAUDE.md` §7). The owner is in brackets.

- **F-661A-2: the search pill looks like a second active item when the rail is collapsed.** Under A, the pill's mint fill (`bg-sidebar-accent`, `frontend/components/shell/app-sidebar.tsx` search pill) is the same colour as the active item's pill, so in the collapsed icon rail it can read as a second active item. This is a design note, not a contrast failure, and it is not in the ruling's "also in scope" list. [662A register; LOW]
- **The collapsed rail hides the last FEES items at 768 px high (pre-existing).** At 1024×768 with the rail collapsed, the last FEES icons are below the fold of the rail (it scrolls). This is today's behaviour. 661B keeps today's rail height exactly (it drops the container's vertical padding, F-661A-8), so it neither causes nor fixes this. [662A register]
- **F-661A-4 correction: the inset costs 8 px of content width, not 16 px.** The 661A probe (`scheme/scripts/dark-inset-check.txt`: `sidebar-inset` width 1184 → 1176) shows the expanded inset takes 8 px (the right margin only; `ml-0`). Collapsed, it takes 32 px: the gap grows 48 → 64 px, plus `ml-2` and the right margin. [664B note]
- **`frontend/CLAUDE.md` is now stale on two lines.** "Accent uses `bg-teal-600`" (Button bullet, line ≈151) and "`--sidebar` → slate-950 (dark sidebar, both modes)" (line ≈115). The accent recipe is now `bg-(--button-accent)` and the firm light rail is `oklch(96.5% 0.005 260)`. Not edited here (not in the file plan). [docs follow-up]
- **The app `:root` sidebar values (the slate-950 rail) are no longer painted anywhere in light.** Only the firm shell renders a sidebar, and the firm block overrides those values there. They are kept unchanged: R1 says no existing token value changes, and the existing light-suite tests pin them. [670A note]
- **`ui/dialog.tsx` close button: `data-[state=open]:bg-accent` probably never applies.** The Radix Close button carries no `data-state`, so the class has nothing to match. This is the shadcn default; it is not "fixed" here. [none; informational]
- **K-04 stays outside the firm shell by design.** Marketing `/`, `/request-access`, `accept/[token]` and platform-admin keep the white-on-teal-600 accent (3.16:1) and its menus in light, because FD-2 rules "firm app only" and those routes render no `data-app-shell`. [FD-2; informational]
- **K-21 (dark accent contrast) is still open.** Dark `--button-accent` is teal-600 (3.16:1 with white) and dark `--accent` is teal-500 (2.25:1 with white). FD-1 kept K-21 in the backlog. `token-contrast.test.ts` pins both values so a later fix has to update the test on purpose. [backlog]
- **The non-firm light canvas fails 3:1 for `--chart-4`.** Amber `--chart-4` is 2.96:1 on the 97.2 % shared light canvas (F-661A-5, pre-existing). No chart renders outside the firm shell, so `chart-palette.test.ts` asserts the firm light canvas (= the card) and the dark canvas only. [backlog]
