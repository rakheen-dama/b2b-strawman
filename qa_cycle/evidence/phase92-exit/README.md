## How to run (single-shot per stack)

The spec posts back-dated entries on the seeded primary trust account and completes the month's
reconciliations; a second run on the same stack is refused ("This period is already reconciled", 652C)
and step 1 fails fast on a used stack. Never overlap with a backend Maven verify.

```bash
# 1. fresh stack, from the worktree root (reseed does not wipe)
bash compose/scripts/e2e-down.sh && bash compose/scripts/e2e-up.sh
```

Terminal A — the portal (not part of the e2e compose stack) against the e2e backend, on :3002 (CORS allows
it). Leave it running for the whole run; stop it afterwards.

```bash
cd portal && NODE_OPTIONS="" NEXT_PUBLIC_PORTAL_API_URL=http://localhost:8081 pnpm dev
```

Terminal B — the exit month alone, its own Playwright project (ruling 652E D-12), from the worktree root:

```bash
cd frontend
EXIT_MONTH_EVIDENCE_DIR=/tmp/exit-month-run \
PLAYWRIGHT_BASE_URL=http://localhost:3001 PORTAL_BASE_URL=http://localhost:3002 \
PLAYWRIGHT_HTML_OUTPUT_DIR=/tmp/exit-month-report PLAYWRIGHT_HTML_OPEN=never \
NODE_OPTIONS="" pnpm test:e2e:exit-month --reporter=line,html > /tmp/exit-run.txt 2>&1
#    (run 6 ran exactly this, with its own /tmp dirs, on nvm node 20.11.1, pnpm by absolute path, under caffeinate -is)
```

**Evidence goes to a per-run directory, never here.** The spec writes the CSVs, screenshots, the refused
complete's JSON and `psql-output.txt` to `EXIT_MONTH_EVIDENCE_DIR` (default `<os tmpdir>/exit-month-<timestamp>/`;
the first test logs the path). This directory holds the copy of ONE chosen passing run: replace `csv/`,
`screenshots/`, `step-10-complete-refusal.json` and `psql-output.txt` from that run's dir, `run.txt` from the
line output (ANSI stripped), and `playwright-report.tar.gz` from the HTML report dir — wholesale, never mixed
across runs. Screenshots widen the viewport and lift the content column's `max-width` until no table scrolls
sideways, so every column of the report tables is in the capture.

`PORTAL_BASE_URL` has no default: unset, step 19 FAILS with a message pointing here (ruling D-3). Step 21
needs `docker` on the PATH (it runs `docker exec e2e-postgres psql …`). The default lifecycle run
(`pnpm test:e2e:legal-lifecycle` = `--project chromium`) does not include this spec.

## Mechanism notes (no figure is changed by any of these)

- **G is the seeded primary account** "Mathebula & Partners Trust Account" (ruling D-1): every posting,
  ledger, other-creditors and investments screen binds to the primary account, and there is no way to make
  another account primary. Step 1 asserts it has no transactions and no reconciliation. The G statement keeps
  its literal first line (`… Acc 0123450001`): the import does not check the account number.
- **I-A and I-B** are created in Settings → Trust accounting (Investment, "Section 86(4) — invested on a
  client's instruction", primary unticked — a non-preset create defaults to primary), opened on the 1st.
- **Clients and matters** are API set-up (`createActiveClient`, `createMatter`): the posting pickers list
  ACTIVE clients only. Each client's email is its auto-provisioned portal contact.
- **Fee note (ruling D-7):** 4 h of billable time on M1 at a matter rate of R 2 000,00 (+ 15 % VAT) =
  **R 9 200,00**, approved and sent (a fee transfer can be recorded against an approved fee note, but its
  approval posts a payment, which needs it SENT). The R 8 500,00 fee transfer (#4) leaves R 700,00 due.
  An exact R 8 500,00 fee note would need an ex-VAT subtotal of R 7 391,30 (×1,15 = 8 499,995 — a rounding
  trick), so the larger fee note was chosen.
- **Approvals:** Alice records, Bob approves in his own browser session (one context per user, so Alice's
  reconciliation wizard stays open from step 9 to step 15). Alice's own approval of #3 is refused with the
  detail sentence the UI shows ("The transaction recorder cannot be the sole approver. …").
- **Generated references:** the placement and withdrawal references are read from the transactions page
  (`INV-` + the investment id's first 8 hex, upper case; the withdrawal `INV-WD-` + the same hex) and copied
  into the CSVs, which are written after the postings.
- **I-A's second match (ruling D-8):** the wizard cannot re-run auto-match; after the withdrawal (done in
  Alice's other tab) the spec goes Back → Review Matches (re-reads the unmatched rows, recalculates) and
  matches the −50 380,00 line to the `INV-WD-…` row in the review pane.
- **The refused complete (ruling D-9):** Complete is disabled in the UI while unbalanced, so step 10 calls
  `POST /api/trust-reconciliations/{id}/complete` once, with `expectedBankStatementId`, and asserts one 400,
  title "Reconciliation does not balance", detail = the G1 sentence (adjusted bank R101 630,00 vs cashbook
  R100 380,00, difference R1 250,00, as at the 31st) followed by the G4 sentence ("1 statement line is
  neither matched, recorded nor excluded.") and nothing else.
- **Allocation description:** the firm's client-ledger history has no description column; the receipt date
  in the allocation's description ("Deposit received 20 October 2026 — CASH DEPOSIT BRANCH 0045") is read
  from the ledger rows by API (read-only) in step 13 and seen on screen in Khumalo's portal (step 19).
- **Firm totals (step 15):** no single screen shows the firm's unadjusted bank (123 225,00) or adjusted bank
  (121 725,00); the spec sums the three accounts' observed figures (found.md F-652E-1). Firm cashbook, client ledgers,
  investment creditors, Fund, unidentified, creditors and difference are the trust-position report's
  firm-wide cards.
- **Rule 54.15 (ruling D-5):** the three per-account locked lists, plus the firm-wide "Trust Creditors List
  (Rule 54.15)" report as at the 31st (client rows general / invested / total; exactly three Fund lines, one per account, each 0,00; the open
  unidentified deposit; Bank Total 101 630,00 + Investment Account Total 20 095,00 vs Creditor Total
  121 725,00).
- **Rule 54.28 (step 17):** the schedule has no firm-total card (found.md F-652E-2); total gross interest (1 734,56) and gross
  charges (172,50) are the sums of its rows.
- **Section 35 (ruling D-6):** the pack is per account — run for G, I-A and I-B; G's sweep and I-A's sweep
  are each asserted with their statement file and line number (the line number read from the wizard).
- **Portal labels (ruling D-4):** "Held in trust" headline = general + invested; the breakdown labels are
  "In the firm's trust account" and "Invested on your instruction (section 86(4))".
- **Timeouts (ruling D-10, revised by D-13):** per-test `test.setTimeout` only; the legal-lifecycle config's
  `globalTimeout` stays at its original 600 000 ms (the run takes ~1.5 min). Stage B's raise to 30 min was
  reverted in review round 1.
