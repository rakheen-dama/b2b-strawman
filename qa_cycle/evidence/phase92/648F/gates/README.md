## Notes

- **SoA dialog Download PDF fails on the e2e stack.** The dialog shows "Failed to download document." This is the known environment issue in 628F `qa_cycle/evidence/phase88-rewalk/628F/builder/blockers/generated-doc-download-env.txt`: the server action follows the presigned S3 URL at localhost:4567 from inside the frontend container. The frontend log shows "The destination stream closed early". It is not caused by 648F. The CTS dialog's Download PDF renders the PDF on the fly and worked through the UI.
- **v15 → v16 reconcile on an existing tenant was not observed.** The stack is fresh, so its only tenant was installed at v16 directly. The startup reconcile runner found no tenants, and restarting would be a v16 = v16 no-op. That path is covered by `LegalZaTemplateReconcileIntegrationTest` (BE verify), not by this OBS. What this OBS proves is that pack v16 installs cleanly and the installed bodies are exactly the v16 bodies.
- **Signs on the statements.** The CTS and SoA Amount columns print the placement as a positive R30 000,00, and the running balance goes down. Sipho's payment is printed the same way. This presentation existed before 648F and is unchanged by it.
- PDF text was extracted with ghostscript `txtwrite`, and the page PNGs come from ghostscript `png16m` at 110 dpi. The HTML page screenshots are the dialog iframe's `srcdoc`, rendered on its own in Chromium at 1280 wide.
- Tree side effect, not caused by OBS: the legal-lifecycle suite run left 26 untracked files in `documentation/screenshots/legal-vertical/*.png`. The orchestrator should restore or ignore them before committing.
