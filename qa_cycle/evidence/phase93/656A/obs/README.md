### Run notes (not defects)

- **Step d ran twice.** The first pass's raw-enum scan joined `textContent` with no separators, so a code next to other text ("ActiveCOMMERCIAL_LITIGATION") had no word boundary and was missed. It reported `[]` for the matter pages, but the screenshot `d-40` plainly shows the code. The scan now joins text nodes with spaces. The second pass (marked in `obs-log.txt`) finds the codes. Both passes had the same lists, teams and tasks. The 655A/655B `obs.cjs` scans join `textContent` the same way, so later slices should reuse this fixed `mainText`. Re-checking 655B's results is out of scope here.
- **Control matter.** To classify OBS-656A-1, step `uiworktype` created one matter in the ordinary New Matter dialog: "OBS 656A UI-created matter (work type control)", client Lindiwe Mthembu, work type "Commercial litigation". That is the 15th `project.created` in the window.
- **Step e is slow (≈4.5 min).** `readGoLive` reads the "acknowledged" element of every item. For an unacknowledged item that element is absent, so each read waits out the 30 s default timeout. This is a script wait, not product latency: the acknowledge PUTs completed within ~0.1 s of each other (`psql-06` timestamps).
- **Results screen and the error row.** Results counts Created / Duplicate — skipped / Failed only. The ERROR row, which is never committed, is not mentioned there. It is visible in the take-on history ("15 (14 / 1)") and as an Error row in the table. This is the same results component and behaviour as the clients dataset (655A). Not filed.
