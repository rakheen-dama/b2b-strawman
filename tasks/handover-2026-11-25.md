## How to work (lessons from this session; also in memory)

- **Cap PR scope.** A fix PR covers its own bug plus its own regressions. New findings become backlog lines. At most one MEDIUM review-fix round. The founder said "going in circles" and "small PRs take half a day"; see memory `feedback_post_fix_scope_cap`.
- **Batch small items into one PR.** Each PR costs about 1.5 h minimum: a 27-min verify, about 25 min of CI, E2E, and reviews.
- **Gate order:** targeted tests → full verify (`backend/scripts/verify.sh`, run detached with `nohup` plus a done-file) → frontend gate (nvm node 20, `/opt/homebrew/bin/pnpm`) → E2E on a fresh stack → two Opus `feature-dev:code-reviewer` reviews plus CodeRabbit.
  - CodeRabbit is often rate-limited; never authorise an on-demand (paid) review.
  - Record `## Verdict: APPROVE @<head>` twice plus `## CodeRabbit: REVIEWED|DEFERRED` in the PR body.
- **Merging:** run the squash merge pinned to the head SHA (`--match-head-commit`) as a single command on its own. Confirm the PR state is MERGED, and only then delete the branch. The merge-gate hook rejects the merge command text anywhere in a compound or multi-line command, including heredocs.
- **Bookkeeping:** commit from a worktree, never in the main checkout. Copy the markers, write the decisions row, push to main.
- **Evidence:** save as `.txt`, because `*.log` is gitignored.
- **Keep the head stable:** do not commit to an approved head (it voids the verdicts). Carry docs into the post-merge bookkeeping commit instead.
- **pkill patterns:** exclude your own monitor commands.
- **Stalled agents:** check idle agents proactively. They can stall "waiting on" a run that has already finished.
- **The runner** (`scripts/run-phase.sh`) now uses a hang watchdog instead of a fixed cap, and checks `origin/main` for Done rows.
- **Machine:** `~/Projects/2026` is excluded from Spotlight. Load fell from about 100 to about 11.
