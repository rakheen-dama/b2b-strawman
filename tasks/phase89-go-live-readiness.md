# Phase 89 — Go-Live Readiness: Trust, Compliance, Documents and Portal Correctness

Phase 89 is a **go-live correctness phase**: no new entity, table (beyond one global marker table), enum value, capability, page family or navigation zone. Phase 88 closed the Phase 87 capstone's 24 root-cause units and re-walked the legal-za 90-day story on the real Keycloak stack; the verdict was **FAIL, not demo-ready** — 63 open gaps (3 HIGH · 15 MEDIUM · 45 LOW) in `qa_cycle/evidence/phase88-rewalk/full/gaps.md`. The three HIGH gaps shipped pre-phase as standalone PRs (#1716 SA business clock, #1717 identity-based document keys, #1718 explicit contract parties — recorded as ADR-358/359/360) together with #1719–#1721 (seven more gaps). Phase 89 designs the rest: three trust corrections (Section 35 pack wiring, interest-run approval surface, server-side running balance), two POPIA wire-shape repairs with a contract pin, letterhead on every client-facing document and a payment receipt a client can download, template tasks and court dates and prescriptions on the portal, six firm-side MEDIUMs plus three triaged-in LOWs (C1, C2, C3, C5, C6), the authorised scenario amendments, and an exit gate of **0 HIGH + 0 MEDIUM** observed by a targeted Keycloak re-walk plus the three Playwright suites on a fresh stack (founder decisions 2–3, 2026-11-03). Architecture: [`architecture/phase89-go-live-readiness.md`](../architecture/phase89-go-live-readiness.md) (Section 14 — §14.3 flows, §14.7 migrations and backfills, §14.8 file-level change tables and test strategy, §14.10 capability slices, §14.12 open questions and the B-table); ADRs [358](../adr/ADR-358-product-wide-sa-business-clock.md)–[365](../adr/ADR-365-wire-shape-contract-pins-compliance.md); binding rulings `.arch-rulings-phase89.md` (§2 per gap, §5–§7 amendments — where the rulings and the architecture differ, the architecture wins); requirements [`requirements/claude-code-prompt-phase89.md`](../requirements/claude-code-prompt-phase89.md) (constraints, E7 exit gate, out of scope; its E2/E3/E6 "Closes" lines are stale — §14.1's scope table is the truth).

### Architecture Decisions
- **Seeder wired on both call sites, gated on the vertical profile, on the 625E shape with an empty `RECONCILE` so the next definition edit reaches existing tenants by a version bump; the page gates on both capabilities and the controller keeps `FINANCIAL_VISIBILITY`** (§14.3.1, §14.6.6, §14.7.5, [ADR-356](../adr/ADR-356-pack-content-reconciliation.md); §14.12 #1 open).
- **Two additive read-side fields are the whole backend change for interest runs; the wizard stays the single UI and opens on an existing run; no cancel state, no detail route** ([ADR-362](../adr/ADR-362-interest-run-draft-approval-surface.md), R6.10; §14.12 #2 open).
- **The running balance is computed server-side in posting order over posted rows; non-posted and REVERSAL rows carry null; filters bind after the window in the same query; `Pageable` unsorted with a `countQuery`** ([ADR-361](../adr/ADR-361-client-ledger-running-balance-server-side.md), R6.7; §14.12 #3 open).
- **422 for a well-formed upload whose content cannot be processed; no exception move** (§14.3.4).

### Non-scope

### Architecture Decisions
- **Rendering omission lives in the template (`conditionalBlock isNotEmpty`), pasted into every client-facing template; the pack `reconcile` keeps the copies in step on existing tenants; four templates, not two** (§14.3.9, §14.6.4, R6.5, [ADR-353](../adr/ADR-353-firm-letterhead-settings.md), [ADR-356](../adr/ADR-356-pack-content-reconciliation.md)).
- **A receipt is one generated document per completed payment event — a nullable FK on `payment_events`, no receipt table, no new category; the number is stored and monotonic; reversal deletes the receipt; AFTER_COMMIT generation with an idempotent lazy fallback; fee-note downloads filter by template id** ([ADR-364](../adr/ADR-364-payment-receipt-as-generated-document.md), §14.2.1, §14.3.10, §14.6.2, B2, B6, B8, B11, R6.2, R6.3, R7.4; keys are per-upload UUIDs per [ADR-359](../adr/ADR-359-identity-based-generated-document-keys.md); INTERNAL, no e-mail per [ADR-350](../adr/ADR-350-client-emails-explicit-intent.md)).
- **Pack entries declare `requiredContextFields`; the seeder writes the column and an additive reconcile field re-applies it; dotted paths; warn-and-acknowledge, never a block** (§14.3.11, B12, [ADR-360](../adr/ADR-360-explicit-contract-party-fields.md) consequences).
- **Period default from `periodEnd`, not `generatedAt`; "today" is `todayInSA()`** (§14.3.12, [ADR-358](../adr/ADR-358-product-wide-sa-business-clock.md)).
- **Pack version chain v11 → v12 → v13, each next free at build; the first tenant DDL creates V10** (§14.7, R6.6).

### Architecture Decisions
- **One owner for "is this matter client-linked": the extracted publisher; the live loop carries the template `sortOrder`, the backfill inserts missing rows at 0 and never overwrites** (§14.2.5, §14.3.13, B5, R7.2, R7.3).
- **One shared global marker table keyed by `(backfill_name, tenant_schema)`; markers are global because the runners decide "already done?" before binding a tenant scope; provisioning and demo cleanup delete a schema's markers** (§14.2.3, §14.7.2, rulings §5, B3, R6.11, R7.1).
- **Four sealed records with typed components that omit the confidential fields; owning-client visibility; cancel / interrupt delete; backfill = SCHEDULED + future only; `FILING_SCHEDULE` dormant; no mark-read** ([ADR-363](../adr/ADR-363-portal-deadline-sync-court-dates-prescriptions.md), [ADR-256](../adr/ADR-256-polymorphic-portal-deadline-view.md), [ADR-253](../adr/ADR-253-portal-surfaces-as-read-model-extensions.md), §14.3.14, §14.6.1, B4, B10, R6.4, R7.7; §14.12 #5 open).
- **Label maps on the portal; the DTO carries `matterName`; the raw-enum guard is a sibling of the terminology guard in its own file with its own allow-list** (§14.3.15, §14.6.5, B9, [ADR-357](../adr/ADR-357-terminology-guard-extension.md)).
